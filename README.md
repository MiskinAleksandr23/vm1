Запуск:

```bash
clang++ -std=c++23 -O3 main.cpp -o main && ./main --debug
```

или 

```bash
clang++ -std=c++23 -O3 main.cpp -o main && ./main
```

Флажок "--debug" выводит промежуточные шаги, например:
```text
Offset = 8 (in bytes), time = 2.323213375
Offset = 16 (in bytes), time = 2.311644625
Offset = 32 (in bytes), time = 2.295315041
Offset = 64 (in bytes), time = 0.713898875
```

Кратко про все три идеи:
1. CacheLineSize - будем полагаться на протокол когерентности кэшей. Идейно давайте просто возьмем два size_t и будем из разных потоков их инкрементировать. Cделаем так чтобы разница(в байтах) между ними была вот $8, 16, 32, ...$ и будем замерять время. Пока они попадают в одну кэш линию - эта линия будем прыгать между ядрами(вообще ос не это гарантирует, но тут я думаю на всех нормальных машинах это будет так - если прям точно то можно запининить поток к разным ядрам (Linux: sched_setaffinity)) и сильно замедлять программу(например у нас в переходе $32 \rightarrow 64$ ускорение в $3$ раза)

2. Размер L1 кэша - Пусть X - размер рабочего набора. Уже знаем размер кэш линии, давайте сделаем в некотором смысле цикл: То есть в ячейке данных будет указатель(у меня это индекс, это неважно) на следующую(в цикле) для этого случайно перемешаем все сначала. Ну и stride чтобы все в разных кэш линиях лежало. Теперь если $X$ становится больше $L1 $ $Size$ то время обращения растет.

3. Ассоциативность - уже знаем размер L1 кэша и кэш линии. Будет два вычисления: Первое обращается к ячейкам $T, T + L1Size, T + 2 * L1Size, ...$, а второе $T, T + L1Size + L1CacheLineSize, T + 2 * L1Size + 2 * L1CacheLineSize, ...$, иначе говоря в первом кэш линии должны попадать в один $CacheSet$ (это не прям гарантия процессора, а известное предположение), а во втором в разные (аналогично предположению). Точно так же провязывается в цикл, только там элементов $lines$ (у меня $2...34$)

Размер L1 кэша тут имеется в виду $L1d$. Посчитать $L1i$(то есть для инструкций) сложнее - видимо можно(или нужно?) сгенерировать какую нибудь $asm$ программу длинную чтобы не полагаться на то что сделает компилятор. Но все равно сложно там(например на x86-64) какой нибудь кэш декодированных инструкций будет влиять.
